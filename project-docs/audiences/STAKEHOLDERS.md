# Stakeholder and Approver Guide

Before development, approve the project brief, reference direction, design system, content architecture, page/component map, and the planned conversion paths. For migrations, also approve URL keep/rename/retire decisions and redirects.

You approve content and business decisions; the shared-component policy protects the technical system. If a requested layout is not supported, the team will propose a reusable variant rather than making a page-only exception.

Before launch, approve staging only after content, forms, tracking, SEO, redirects (when applicable), and responsive checks have evidence. A deployment status alone is not launch proof.
