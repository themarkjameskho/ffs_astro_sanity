# Developer Entry Point

1. Read `AGENTS.md`, `START-HERE.md`, the selected track, `LIFECYCLE-CHECKLIST.md`, and `standards/COMPONENT-AND-CONTENT-STANDARD.md`.
2. Treat `studio/schemaTypes/documents/page.ts` and `src/components/sections/SectionRenderer.astro` as the authoritative registered-section boundary.
3. A schema/component change is complete only after schema, TypeScript, every GROQ projection, section contract, canonical renderer, shared component, Studio/readback, and affected-route verification are complete.
4. Put brand differences in tokens and approved shared variants. Do not make a page template or presentation branch.
5. For a WordPress migration, preserve substantive content, URL/SEO/media data, and redirect evidence before you normalize layout blocks.
6. Run the project checks and route/viewport checks required by the lifecycle stage; report the exact result and what remains unverified.
